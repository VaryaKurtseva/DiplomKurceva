# Название проекта:
«Разработка модели машинного обучения для выявления потенциальных пробелов в тестовом покрытии по изменениям программного кода»

# Цель проекта:
Разработать и обучить модель машинного обучения, способную на основе анализа исходного кода, существующих тестов и изменений между версиями программного проекта определять потенциально непокрытые тестами сценарии и предлагать дополнительные проверки. (Оценивать покрытие и предлагать кейсы)

# Идея проекта:
На вход модели поступают данные из Git-репозитория: изменённый код (diff коммита), связанный с ним исходный код и существующие тесты. Система анализирует характер изменений и определяет, какие сценарии поведения программы уже проверяются тестами, а какие потенциально остались без проверки.

Основной результат работы — обученная или дообученная модель ИИ, выполняющая анализ новых изменений кода и формирующая рекомендации по дополнительным тестовым сценариям, на основе оценки покрытия существующими тестами.

# Основные этапы работы:

1. Сбор и подготовка данных. Формирование датасета из программного кода, Git-коммитов, diff изменений и соответствующих тестов. Очистка и преобразование данных в формат, пригодный для обучения модели.

2. Анализ данных. Исследование взаимосвязи между изменениями программного кода и изменениями тестов, выделение признаков, характеризующих тип и масштаб изменения, анализ покрытия кода.

3. Разработка модели. Выбор базовой модели для работы с программным кодом и её дообучение на подготовленном датасете для решения задачи анализа изменений и тестовых сценариев.

4. Оценка качества. Формирование тестовой выборки и оценка способности модели обнаруживать недостаточно протестированные изменения. Сравнение результатов модели с фактическими тестами и эталонными примерами.

5. Инференс модели. Реализация механизма, позволяющего передать модели новый commit/diff и существующие тесты, покрытие и получить результат анализа.

Входные данные модели:

- исходный код;
- изменения между версиями кода (Git diff);
- существующие unit/integration-тесты;
- при необходимости метаданные коммита и результаты запуска тестов.

Выход модели:

- оценка достаточности существующих тестов для внесённых изменений;
- перечень потенциально непокрытых сценариев;
- описание дополнительных проверок, которые рекомендуется добавить;
- при расширенном варианте — генерация заготовок дополнительных тест-кейсов.

# Итоговый артефакт:
Дообученная модель машинного обучения для анализа изменений программного кода и тестового покрытия, подготовленный датасет, результаты оценки качества модели и прототип механизма инференса для анализа новых коммитов.
